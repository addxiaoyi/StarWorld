# 架构与运行边界

## 权威与模块

StarCore 唯一拥有国家、城市、成员、领土、科技、政策、国家繁荣、资源、天气、时代、战争和外交。`CoreBridge` 从公开 API 获取身份、授权和双层领土；`CoreExtensionPort` 把天气、纪元、战争、外交、加工等公开服务复制成不可变快照。没有反射私有字段、直接 SQL 或打包核心实现。真实国家/城市无法证明存在时停用相关行为，保留扩展财产。

| 模块 | 数据与职责 |
| --- | --- |
| `domain/Simulation` | 地区储量、维护与顺序配方、事件/余波、周期结算 |
| `evolution` | 城市规划/专长、知识、稳定、本地繁荣、军需、文化影响、历史与条件事件 |
| `logistics` | 有限节点和路径、容量/维护、双向托管、运输进度、供需及完成回执 |
| `life` | 职业、真实物资活动、CE 家具复核、受控现场演奏和限额贡献 |
| `integration/ResourceOutbox` | 实物成本预扣、国家幂等请求、租约、receipt 核对与恢复 |
| `runtime` | Paper现场采样、单线程IO协调、扩展接线与关闭 |
| `ui`、`api` | 玩家授权、GUI、防物品拿取、异步只读快照与提交后通知 |

`nation_state` 是核心国家 UUID 的文明附加属性；`evolution_city` 的繁荣不是另一份国家繁荣权威。地区以登记设施区块标识，文化只在已登记地区增量积累，不预生成全世界分区。

## 线程、批量与性能

Paper 主线程调用 StarCore、读取已登记锚点/CE 家具、采样同城听众、操作 GUI 和背包。不可变 UUID、数字、字符串、集合快照进入专用 `StarWorld-storage` 单线程，处理 JDBC 和纯模拟。回调通过调度器返回玩家或主线程；不能在主线程 `join()` 数据库 Future。

每 40 tick 轮转已登记城市；默认每批 20 城、每城 12 设施，上限均可配置。交通和 outbox 有独立有限批次，未完成时不叠加同类任务。只验证有限登记节点、设施和家具 UUID；不扫描全世界区块或全部实体，不沿路线逐格寻路，不强制加载区块。附近听众用八格玩家空间查询且凭证最多16人。

同周期重试由持久账本去重，时间回拨拒绝。重启、长停机和分页延迟只处理当前生产周期，不追赶遗漏周期；运输每个实际周期最多推进一次。音乐是有限时间会话，停顿或超时不可继续获得完成奖励。

`city_authority` 持久保存最近一次核心复核的有效性。升级已有城市初始有效；分页复核发现城市缺失或核心状态无法证明时标记无效，国家发展聚合立即排除已标记城市，保留其历史和库存。有效核心快照通过 `ensureCity` 恢复标记。每批先在一个事务中更新全部城市归属/有效性，再允许该批任何城市使用国家加成，避免同批处理顺序造成已知失效贡献。其他分页中的变化最多需要一次完整轮转及IO排队后收敛；国家查询是最近复核状态，不是每次查询扫描整个国家。

## 产业与演化事务

一次模拟事务包含：同步核心身份、周期去重、状态/条件事件变化、每地区本期一次恢复、有效设施维护、顺序配方扣料/开采/入库、城市演化、周期回执及 `last_period`。异常和 `Error` 全部回滚。矿藏默认不可自然再生，注销不删除地区储量。

顺序配方真实消费投入；仓储容量不足时跳过该配方，原料/储量保留，已付维护不退。同城设施按稳定 UUID 顺序处理，下游可能下期才得到上游原料。倍率及物品数量都有限制，原始单位仍为整数，较小倍率不保证每种少量产出都立即增加一件。

仓储容量按每种物品计算：基础为总上限的四分之一（最低64），维护过且当前有效的仓库逐级增加，至配置总上限。容量降低保留已有库存，阻止继续超额入库，不自动删除财产。维护状态与城市容量持久化，实际入库路径包括生产、存入、托管收货与退款，不能借其他路径绕过限额。

城市规划与专长有冷却；知识和有效设施门槛每次核实。学院消费面包/纸后积累知识；市场、水井和食物供应影响本地繁荣/稳定；兵营真实消耗箭形成军需准备。它们不直接替核心发动战争或写国家繁荣。区域传统按有限影响修正产业，贸易文化只凭完成回执传播一次。

## 四种账本边界

| 场景 | 提交与恢复 |
| --- | --- |
| 城市产业/演化 | 同一个SQLite事务完成库存、储量、城市状态和周期回执；重启不重复 |
| 城市托管贸易 | 报价和接受分别预扣双方真实库存；运输完成时双方入库与完成回执共同提交；取消原物退还也整体提交 |
| 生活活动 | 消耗、额度、文化、短期效果与请求UUID共同提交；家具维护本期一次、演奏音符和完成回执持久化 |
| 国家资源输出 | 本地预扣/outbox→核心同事务ID grant/receipt→本地ACK；重启沿用原请求，不能因ACK丢失重复赠送 |
| 城市公共工程 | 固定项目 UUID 和归属；同产业事务扣运行维护与逐期施工材料，完工下一期生效，永久水位去重 |
| 城市生活需求 | 真实生活凭据的全局领取墓碑、仓库成本、有限属性奖励及完成回执在同一事务提交 |

生活文化使用独立已消费回执集合汇入未来的城市演化：本周期城市已结算之后举办的活动在下一次有效周期处理，不丢失，也不把累计文化每期重复计入。消费ledger与模拟使用相同连接和外层事务，模拟失败后仍可再次消费。

城市贸易倾向使用 `evolution_trade_action(city,receipt)` 消费稳定的已完成贸易收据，每城每次结算最多十份；仅匹配收据发生时国家与当前城市国家的记录。收据消费与模拟回执同事务，失败可重试，后续周期和重启不重复累计。区域文化交流另有收据和持久游标，不依赖重复计数最近若干周期的贸易。

国家 outbox 的核心库存与回执契约独立于非幂等国家繁荣接口；后者没有可靠完成凭据，不自动跨库重试。曾发送的出口不能直接退款，因为核心可能已提交。详见[国家事务](core-extension.md)。

## 背包与数据库

玩家文件和 SQLite 不能原子提交。取出先以 `PREPARED` 扣仓库，存入先保存凭据再核实/移除背包物品；整份检查容量、操作后 `Player.saveData()`，然后确认凭据。失败或崩溃的未决操作隔离，不自动重放。活跃操作禁止人工处理；每玩家未核对凭据阻止新开单；`credit/discard` 一次决定并记审计。

此边界不承诺跨玩家文件与数据库的绝对原子性。管理员必须核对真实背包、库存与凭据后决定，不可依据“本地失败”盲目发物品。提交后 Bukkit 事件也不是可靠消息队列，不能据此再发一份产物。

## 森罗与Folia

Cookery/Tavern 只使用已交付并验证真实 CE 身份的商品，不把提交前通知当完成回执。Deco 通过公共 CE 家具接口验证UUID、ID、元实体、位置与当前归属，每期仅对已加载登记家具计算维护贡献；未知API或实体无效则停用。MusicPlus 没有公共完成服务，StarWorld 受控演奏是独立功能，真实播放声音、核实乐器和现场听众后才产生不可变音符凭证。

本版检测 Folia 后停用。仅IO安全或使用GlobalRegionScheduler不足以证明核心服务可跨区域读。`SchedulerGate` 预留全局/玩家/区域调度边界，正式兼容需要：上游发布带版本的不可变权限和状态快照；锚点/家具在位置所属区域验证；背包/GUI/声音在玩家实体线程；跨区域听众快照汇聚并重新检查归属版本；处理退休回调和停服任务；最终通过跨区、传送、退出、卸载、转国与重启真服验证后才声明支持。

## 升级和备份

基础配置 v1 备份迁移 v2；基础数据库 schema2 保持兼容，扩展表与索引由各模块初始化。civic schema2 将旧请求表的数值桶唯一约束迁移为冻结绝对窗口检查，保留全部请求、成本、动作领取记录和历史序列；全程启用外键，失败回滚。`life_schema` 等扩展版本单独拒绝未知未来版本。配置未知版本、非法引用、负数或非有限倍率拒绝启动，不删库。旧 ID 优先的扩展定义保留管理员覆盖。

正常关服后备份整个插件目录，包含配置、SQLite、WAL和未决凭据；恢复到对应插件版本。测试可在新存档设置10–30秒周期，正式存档改周期要安排迁移。关闭会阻止新任务、注销监听和API、等待IO终止再关闭数据库；不能在IO仍运行时强行关闭连接。
