# 后续版本计划与验收边界

用户选择继续按原始六系统深化玩法，由本项目安排版本。0.3.0 的既定交付已完成，证据见[历史报告](history/test-results-0.3.0.md)。以下计划是后续工作清单，尚未通过的版本不能引用旧 JAR 的测试结果。

| 版本 | 玩家能做的事 | 开发和验收边界 |
| --- | --- | --- |
| 0.4 规划与经营反馈 | 比较已登记商路的运时、容量和双方维护物资；按真正到货的商品看贸易统计；管理员在线备份长期存档 | 已通过245项自动化、117个实服阶段及缺依赖双启动；含三次启动经营验收、0.3→0.4升级和最新森罗候选。路线比较不授予通行权，付款不等于到货 |
| 0.5 灾害应对与地区恢复 | 干旱、洪水、饥荒各选择两种有真实物资成本的应对方案；比较短期生产缓解与长期恢复的取舍 | 独立工作区开发中。按事件与请求凭据去重，只恢复可再生资源；失地暂停，不补离线周期，不更改核心天气 |
| 0.6 城市长期建设与文明分工 | 投资农业、军工和文化公共工程，使设施、知识、文化及地区资源共同决定建设路线 | 需同库保存项目、投入、周期和完成回执；要求有效设施和当前归属，不能凭空创建国库资金或复制核心科技树 |
| 0.7 生活与治理界面 | 在城市界面查看工程、灾害、物资缺口和生活贡献，按实际食材、家具和演奏完成城市需求 | CE内容和森罗模块继续可选；只消费实际提交的物品/活动凭据，不猜测上游生产完成 |
| 1.0 连续世界验收 | 两国多城以粮食、木材、军需、贸易、灾害和文化形成长期发展路线 | 完整升级、重启、损坏/失地、战争封锁和恢复流程；交付最终JAR、源码、配置、API和原始测试证据 |

每版按其改动执行有意义的自动化与实服测试，保留失败/中断记录，先固定源码和 JAR 再运行实服。第三国过境、自动上游生产归因、Folia运行和全图道路识别仍需相应公开契约；这些能力不会通过绕过核心权威或开启不安全调度来“完成”。Folia按原始任务保持迁移规划，正式兼容声明须另有上游契约和跨区实服证据。
