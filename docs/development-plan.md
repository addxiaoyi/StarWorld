# 后续版本计划与验收边界

本计划按原始六系统逐版深化。每一行状态只引用该版本的验证材料，历史JAR的通过记录不会转用于新版本。

| 版本 | 玩家能做的事 | 开发和验收边界 |
| --- | --- | --- |
| 0.4 规划与经营反馈 | 比较已登记商路的运时、容量和双方维护物资；按真正到货的商品看贸易统计；管理员在线备份长期存档 | 已通过245项自动化、117个实服阶段及缺依赖双启动；含三次启动经营验收、0.3→0.4升级和最新森罗候选。路线比较不授予通行权，付款不等于到货 |
| 0.5 灾害应对与地区恢复 | 干旱、洪水、饥荒各选择两种有真实物资成本的应对方案；比较短期生产缓解与长期恢复的取舍 | 已通过291项自动化、22阶段救灾实服和7阶段0.4升级。按事件与请求凭据去重，只恢复可再生资源；失地暂停，不补离线周期，不更改核心天气 |
| 0.6 城市长期建设与文明分工 | 投资农业、军工和文化公共工程，使设施、知识、文化及地区资源共同决定建设路线 | 随 1.0 实现。同库保存项目、投入、周期和完成回执；要求有效设施和当前归属，成本来自城市仓库 |
| 0.7 生活与治理界面 | 在城市界面查看工程、灾害、物资缺口和生活贡献，按实际食材、家具和演奏完成城市需求 | 随 1.0 实现。CE 内容和森罗模块可选，只认已提交的物品及活动凭据 |
| 1.0 连续世界验收 | 多国多城以粮食、木材、军需、贸易、灾害和文化形成长期发展路线 | 已通过同一 JAR 的 398 项自动化、9 套 185 个实服阶段及无依赖双启动；含 0.5 存档升级和最新已审计森罗候选。详见[测试结果](test-results.md) |
| 1.1 长期世界与恢复治理 | 调整生活贡献上限仍能逐期计入旧贡献；积压交易公平派发；运输限制变化后旧货物可暂停、取消或改道；停服不遗留永不完成的排队 Future | 444项自动化，life source/carry 4+7阶段、物流14阶段和0.5存档升级7阶段均通过；历史证据见[1.1归档](evidence/history/1.1.0/acceptance-status.md) |
| 1.2 逐世界气候与产业韧性 | 依据已验证设施所在世界的国家天气选择农作物和矿业产地；建成并维护灌溉水网缓冲农田逆境 | 455项自动化与同一JAR独立Paper双启动已通过；实际生产StarCore上的天气产业端到端与1.0业务全量同JAR重跑尚待完成，详见[1.2验收](evidence/1.2-acceptance-status.md) |

每版按其改动执行有意义的自动化与实服测试，保留失败/中断记录，先固定源码和 JAR 再运行实服。第三国过境、自动上游生产归因、Folia运行和全图道路识别仍需相应公开契约；这些能力不会通过绕过核心权威或开启不安全调度来“完成”。Folia按原始任务保持迁移规划，正式兼容声明须另有上游契约和跨区实服证据。
