# 灾害治理界面与操作

使用 `/sw disaster-menu`，或在城市主页、`/sw develop` 的“灾害治理”入口打开界面。需要 `starworld.use` 和当前 StarCore 城市成员身份；普通成员可查看策略、成本和本城历史，提交响应还需要当前城市管理权限。本文是操作说明，自动化与实服验证结果以 [测试结果](test-results.md) 为准。

## 从预览到提交

策略页显示配置中的全部治理方案，默认包括干旱灌溉/配给、洪灾排水/迁置、饥荒公益厨房/进口救济。点击某项只打开预览，不扣仓储物品。

确认页展示适用事件、所需设施、每项真实成本和当前仓储量、负面损失缓解比例、每步恢复上限、最多步骤、恢复总预算和期限。设施状态来自当前已加载、双层领土有效的登记锚点；界面不会扫描未登记区块或强制加载区块。缺少管理权限、匹配灾害、有效设施或实物库存时，确认按钮显示明确阻止原因。进口方案还需要近期已完成的实际物流进口回执，服务端在提交时核实；界面预览不承诺该条件已经满足。

点击“确认支付并救灾”后，依次重新读取城市状态，在 Paper 主线程复查成员、城市/国家归属、使用和管理权限以及实际设施，再由存储事务核对原事件、库存与进口回执并扣费。预览后事件被替换会拒绝新的响应，不把旧预览改成另一场灾害的订单。提交成功显示持久请求回执，并进入响应状态页。

每个确认页只生成一个请求 UUID。重复点击同一确认页使用同一个 UUID，后端返回原回执，不重复扣料；UUID 显示在确认页和成功消息中。重试仍须证明扩展城市当前有效（active）、当前所属国家与请求原国家相同，以及调用人的当前权限。同权限历史重试可返回旧事件、旧请求周期的原回执，不会把历史请求改为新事件；城市转国或失效时不能借旧 UUID 绕过当前归属检查。刷新或重新打开预览会生成新的 UUID，但同一城市、原国家和事件开始周期仍只允许一个响应。失败时可保留确认页重试，也可使用显示的 UUID 执行 `/sw disaster respond <策略ID> <requestUUID>` 对账。

## 状态、历史与生效规则

底部可切换“治理策略”“响应状态”“治理历史”，并返回发展面板或刷新。状态/历史每页最多8条，并服从 `disaster-response.yml` 的更小 `limits.max-page` 限制；上一页/下一页只发起有界只读查询。

状态页展示原事件与国家、生效/截止周期、恢复步骤、剩余预算、最近恢复周期和已支付成本。它会区分等待次期、已结束与原国家响应暂停；正在执行的响应也必须在结算时继续通过真实设施和归属复核。历史页展示已提交的请求和恢复记录，不把预览或失败请求当作已完成救灾。较长记录在物品说明中截取，可通过 `/sw disaster history [页]` 查看聊天记录。

响应最早从请求周期的下一周期生效。短期缓解只能把负面事件倍率拉回1，不会放大丰收等正向事件。长期恢复在正常城市演化完成后，与资源、库存和周期回执一起提交；每个实际结算最多一步，不补算停机期间遗漏周期。恢复总预算按“稳定 → 繁荣 → 自然资源”的顺序共享：属性按实际封顶增量向上取整（ceil）收费，例如从99.5恢复到100只增加0.5并消耗1预算；已满100不收费，余额再供后续属性或资源使用。地区资源按实际恢复数量消耗预算，受当前地形容量限制。资源仅恢复配置允许的可再生肥力/林木，不再生矿石。原国家归属或必需设施失效时暂停恢复。

所有展示物品和拖动都受原 CityMenu 的取消规则保护，Shift、数字键、双击、底部背包点击和非界面拥有者不能提交动作。点击下一 tick 执行时还会核对原菜单；换城、转国、失去使用权限或切换界面后，不执行旧菜单动作。异步读取期间关闭或切换界面也不会重新打开旧治理页面。

命令备用入口：`/sw disaster options`、`/sw disaster respond <策略ID> <requestUUID>`、`/sw disaster status [页]`、`/sw disaster history [页]`。公开只读 Java API 见 [API 文档](API.md)。Folia 仍按整个插件当前能力明确降级，不因增加界面而宣称区域线程支持。
