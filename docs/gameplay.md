# 1.0.0 游玩与验收流程

本文件是可重复的操作方案。已经执行的步骤、实际JAR哈希和失败/限制记录只见[测试结果](test-results.md)，不能把操作方案本身当作验收通过。

## 1.0 城市治理开局

先完成下方的开局产业，积累面包、木板、纸张和石头。城市管理者可以用 `/sw governance` 查看工程、需求、生活贡献与灾害治理；确认页列出实际成本、门槛和库存缺口。缺材料时先补给，重复提交同一确认页不会额外分配工程或奖励。

以粮食城为例：在平原或河流地区登记农场、水井和仓库，另设学院并维持纸张与面包供应。国家选择合适文明，城市使用综合或农业规划，知识达到 2 后，从公共工程选项预览灌溉水网。默认工程本身需合计 48 木板、20 面包和 16 石头，分起建和 3 个实际施工周期支付；设施自身维护另计。完工后下一期开始，持续支付工程维护才能获得农业加成，同时承担工坊倍率取舍。缺少有效设施、失地或材料不足会暂停，补齐后延续原进度。

军工城可投资兵工区，文化城可投资文化街区，二者有不同设施、规划、文明和知识/文化要求。查看工程状态及历史确认具体暂停原因，不能用拆除重登刷新国家工程槽或地区矿藏。详见[公共工程](public-works.md)。

生活需求先发起，再实际开展活动，最后提交材料与凭据：社区聚餐认已提交的宴会，公共空间认不同家具的真实维护，节庆认已完成的现场演奏。已发生但早于请求的动作不能补交，家具登记和未完成演奏也不能替代贡献。缺实际 CE 内容或生活补给时选项会解释原因；原版宴会和音符盒演奏仍有独立路径。详见[城市需求](civic-needs.md)。

遇到干旱、洪水或饥荒时，从灾害治理界面比较两种策略的真实成本、有效期及恢复预算。进口型饥荒响应需要已完成的真实贸易收据；付款或运输中货单不算到货。战争暂停物流后，持续维护、已有库存与和平后的运输恢复会共同决定城市能否继续发展。详见[灾害治理](disaster-governance.md)。

## 开局与产业

1. 使用新测试存档、Java21与Paper1.21.11。默认周期300秒；新测试世界可设10–30秒，随机事件设0便于比较。不要改正式存档的周期。先不装CE/森罗，确认 `/sw status` 明确降级但原版系统可用。
2. 用StarCore真实命令建立国家、城市、成员，并认领国家/城市两层区块领土。非城市成员、非管理者、仅有一层领土和城外锚点应被拒绝。
3. 不同区块放堆肥桶、切石机、高炉，看向六格内分别 `/sw register farm`、`sawmill`、`workshop`。先等农场积粮，林场/工坊才支付面包维护。单独高炉不能凭空产武器。
4. 查询 `/sw stock`、`buildings` 和GUI最后报告：小麦/面包→原木/木板→粗铁/铁锭/箭有真实投入。下游可能因稳定UUID处理顺序延后一周期。
5. 用 `/sw withdraw minecraft:arrow 4` 后在真实背包核实，再存回。改名/附魔/PDC/受损原版特殊物品应保留；背包空间不足不落地物品。异常未决凭据不自动重放，管理员核对 `/sw pending`。
6. 六地形农业倍率依次为山脉0.5、河流1.5、平原1.3、森林0.9、沙漠0.3、雪原0.4；森林林木恢复更快，山脉矿更多，矿藏默认不再生。注销重登不能刷新储量。
7. 国家创始人选择工业文明后，全国登记城市工坊增强、农业减弱；普通市长不能更改全国文明。五种文明均有产业取舍，转型六周期冷却。

## 城市发展与战略分工

| 设施 | 锚点 | 预期效果及真实约束 |
| --- | --- | --- |
| `warehouse` | 木桶 | 木板维护；有效且维护过的仓库提高每物品库存容量 |
| `market` | 钟 | 面包维护；影响本地繁荣，与贸易发展相关 |
| `academy` | 讲台 | 面包和纸维护；积累知识、文化，支持城市专长 |
| `barracks` | 制箭台 | 面包维护并消耗真实箭；战时军需需求更高 |
| `well` | 炼药锅 | 木板维护；改善本地繁荣与稳定 |
| `kitchen` | 烟熏炉 | 面包维护；小麦和原木加工食品 |

1. `/sw development` 查看规划/知识/军需等，`/sw develop` 打开扩展GUI。选择农业、工业、商贸、文化或军事规划，验证有冷却与正负倍率。
2. 学院维护成功后积累知识，满足设施/知识/国家产能门槛才可选择 `/sw specialty granary|arsenal|woodworking|gastronomy`；破坏专长所需设施后相应作用应停止。
3. 比较仓库维护前后的存入/生产/贸易收货上限；拆仓库后保留已有财产，但不能继续超额入库。验证退款满仓时整笔失败且托管不丢。
4. 粮食不足、维护失败、市场/水井和战时补给应影响本地繁荣与稳定。确认国家繁荣权威没有被重复写入。真实军队在有效设施区块交战时，可通过公开army_combat读取当前/前一周期军需和地形贡献；丢领/过期/无供给中性，其他插件最高伤害聚合和玩家PVP范围见[战斗说明](combat.md)。
5. `/sw history` 与 `/sw culture` 查看有限历史和地区传统。长期有效设施增加本国传统；重复同周期不增加。

使用 `/sw nation-development` 查看最近核心复核的有效归属城市聚合的五方向国家倾向、知识、文化和已选国家专长。国家创始人可 `/sw national-specialty agriculture|industry|commerce|military|culture`；默认农业需20农业分数/5知识，工业需20工业/8知识，贸易需3贸易/5知识，军事需20军需/8知识，文化需20文化/10知识。门槛来自实际已提交城市发展，选择冷却六周期。每项全国专长有产业取舍，倍率最多1.15、最低0.85；贡献城市转国或解散后，原国条件不足会暂停该专长加成，但保留选择历史。归属复核按有限城市分页轮转，变更最多需要一次完整轮转及IO排队后反映；解散标记重启后保留，核心重新证明城市存在时恢复。

用 `/sw regions` 比较本城已登记地区储量与恢复，`/sw atlas` 打开分页地图册，`/sw map` 查看上北下南的9×5方位图，`/sw districts` 汇总四向相邻且地形相同的地区。选择适合的农业、林业和矿业区；地图查询不会消耗纸张或改变储量。地图册不发现未登记区块，归属来自最近一次核心复核，不能代替操作时的权限校验。默认每12个有效周期文化衰减一次，核心 `open_diplomacy`、`fortified_borders` 政策影响新增文化；只读查询、停服和同周期重放不会重复推进衰减，见[地区文档](geography.md)。

## 交通、供需和战争

按[交通详细步骤](logistics.md)建立两城的道路/桥梁/港口/关隘节点和显式路线。双方管理者报价并接受后，分别从真实仓库进入托管，运送完成前任何一方都不能领取对方物品。完成时双方入库与唯一收据共同提交，文化交流仅发生一次。

检查节点共享容量、地形运时和真实维护。复制路线不能绕过同一关隘容量；跨世界路线拒绝。路径只声明有限节点，不代表沿途每格道路已识别。

运输中禁用节点、拆锚点、卸载区块、撤销领地或发动真实核心战争，应暂停或冻结并保留托管。恢复后按有限周期继续；停服不补走遗漏周期。城市转国不得把旧国货单悄悄改给新国。未接受报价由报价方取消；已接受可由任一方取消且双方原物同事务退还。`/sw demand` 应反映托管扣除后的真实短缺/过剩，不生成金币。

`/sw trade alternatives <货单UUID>` 查看相同方向的替代路线，`/sw route status <路线UUID>` 查看共享节点运力与瓶颈。一方通过 `/sw trade reroute <货单UUID> <新路线UUID>` 提议，另一方执行 `/sw trade reroute-accept <请求UUID>` 确认后改道，重新计算完整运时；当前期不得重复移动，旧路线已花费运力不退回。许可条件见[交通文档](logistics.md)。

使用国家金币购买实物时，卖城先 `/sw market sell minecraft:bread 20 1.25` 托管20面包，买国创始人选择卖城至买城的有效商路执行 `/sw market buy <挂牌UUID> <商路UUID>`。实际国库转账25.00并核实核心稳定回执后，商品才进入单向物流；到货前不能使用。检查付款重放不再次扣钱、失地/战争暂停后仍保留原货物、停战最终只入库一次。已经尝试支付的单据不能当作普通易货取消退款，恢复规则见[市场文档](market.md)。

## 十一种动态事件

默认事件具有条件和权重，而非每城任意随机所有灾害：干旱取沙漠/核心干旱天气；暴雪取雪地/暴雪天气；洪水取河流；饥荒取真实食物不足；资源危机取战时军需不足或矿藏耗尽；商业繁荣取本次消费的成功贸易收据；节庆取生活/文化；边境资源争端须有效产地仍有资源，四邻存在实际外国领土且对该国处于战争或明确敌对；衰落/复兴取发展状态；丰收要求有有效设施。远方战争与和平邻居均不能触发资源争端，实际证据见[地区文档](geography.md)。

管理员可用 `/sw event <ID>` 单独验证持续与余波。观察库存倍率、本地繁荣/稳定、事件历史和重启后完整时间线；普通成员不能用事件管理命令。事件不改整片世界方块，也不接管StarCore天气或时代权威。

通过 `/sw disaster-menu` 或城市/发展面板的“灾害治理”入口，先预览对应干旱、洪灾和饥荒方案的真实成本与设施，再确认支付。确认页保留稳定请求 UUID 和原事件，提交时复查当前归属、权限、现场设施、库存及进口回执；重复点击不重复扣料。底部可以查看响应步骤、共享恢复预算和已提交历史。具体操作、期限及暂停规则见[灾害治理界面](disaster-governance.md)。

## 生活与国家资源出口

按[生活流程](life-integrations.md)分别验证原版聚餐、真实Cookery菜肴、Tavern饮品、Deco家具维护和StarWorld现场演奏。缺内容不扣物资；家具移动/身份替换/卸载/离开领土无加成；重复登记/本期重算不能刷文化。演奏至少60秒、12音符、5音高、有同城听众、间隔合规；重启找回会话，已结束会话重复完成不发奖。普通 `/kmusic` 不自动算城市贡献。

登记有效仓库或兵营后使用 `/sw export grain|steel|armaments <批数>`。核对实体成本预扣、`/sw outbox` 状态以及**真实核心**同事务ID的receipt与库存。核心不可用应保留RETRY；核心已提交但本地ACK丢失时按原ID恢复，不再次grant。曾发送请求不允许无凭退款，见[恢复规则](core-extension.md)。

## 重启、权限与GUI

同周期重启不重复生产、运输维护、文化传播、生活贡献或国家资源发放。停机不补发遗漏产业。破坏/失地/城市解散停产且无无效设施维护；旧国家设施需要正确归属下重新登记。数据库故障要整体回滚，不出现半份物资或无成本文化。

生产周期长度现有独立持久时钟迁移：关服备份后调整周期，保留已有周期编号，避免新的周期长度将收据编号倒退或重用。已有超出新仓储上限的物资保留且允许逐步提取，新增入库仍按新上限检查。正式存档调整周期会改变剩余事件/冷却的实际分钟数，应安排升级窗口并验证预期。

GUI底栏、Shift、双击、拖动和非界面拥有者操作不能拿取展示物品。异步打开回调遇到换城、关闭界面或离线不能回放旧城动作。城市经理、国家创始人和管理员权限分别核实；管理员也不能给无效领地/锚点制造证据。

自动化测试含真实SQLite事务、并发、重启和独立进程崩溃场景；实际声效、多人听众、CE热重载及跨插件完整套件要在对应测试服单列结果。Folia当前预期是明确拒绝启用，不能以停用成功宣称Folia兼容。
