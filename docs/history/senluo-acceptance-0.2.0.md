## 隔离设置与失败历史

仅隔离服将职业切换冷却从6周期调为1周期、生产周期设10秒、随机事件概率设0；演奏默认60秒和音符/听众约束保持。CE预先加载配置、关闭资源文件内存缓存、分配8000服务端方块槽，不发送客户端资源包。JVM使用768MiB堆、512KiB栈、单逻辑CPU、SerialGC/C1、64MiB code cache、384MiB metaspace，关闭仅此隔离服Spark采样。未停止其他服务器或改变系统全局配置。

CE04首次执行在CE启用阶段中断；第二次因宿主内存不足无法创建native thread而失败。CE05修复前预检发现错误CE物品转换重载与Tavern配方ID误用，已修产品并经172项完整自动化测试后再验；后续执行环境中断均保留为interrupted。CE预置自定义资源时曾遗漏同一JAR中的 `resources/internal/` 默认状态映射，已原样补齐55个静态文件；没有改造原始森罗内容包。测试夹具还曾使用无法正确放置该椅子的CE简化place入口，最终明确调用公开 `place(Location,Key,"ground",false)`；这是夹具修正，没有放宽StarWorld的家具身份、距离或领土验证。失败/中断结果未改标为通过。

家具登记最终使用CE公开 `rayTrace(Player,double)`，六格内命中后通过 `getBukkitEntity()` 回查元数据实体，核对相同UUID/ID、成员和双重领土。每期继续验证原位置、已加载区块及当前归属；不扫描实体或加载区块。
