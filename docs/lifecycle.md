# 长期世界与恢复治理（1.1）

本版深化已有生活、文明、运输和交易系统，所有国家、城市、领土及国库权威仍来自 StarCore。升级前正常关服并备份完整插件目录；life schema2 不能通过直接替换旧 JAR 降级，应恢复升级前备份。1.1 的生命账本 source/carry、物流恢复和 1.0→1.1 升级专项均已有真实服务器通过记录；这些历史结果不代替 1.4 候选 JAR 的重跑。1.4 发行收尾仍需用最终 JAR 重跑生活文化迁移并通过完整证据包校验。完整验收状态见[测试结果](test-results.md)。

## 文化贡献结转

活动已提交的物资成本和原文化回执永久保留。管理员降低生活贡献上限后，一份大于新上限的旧贡献按有效城市周期分期汇入演化。例如25份旧文化在20上限下先计20，剩余5与后续12可在下一期合计17。城市失去原国家归属时停止旧国家的待归集资格，保留原活动及已归集进度。同周期重试和重启共用预算，不能重复计入。

`StarWorldApi.lifeEvolutionCredit(actionId)` 仅按确切 UUID 读取不可变诊断，字段为 `actionId`、`cityId`、`nationId`、`originalCulture`、`creditedCulture`、`lastCreditedPeriod`、`pending`；从未归集时最近周期为 -1。该接口不证明玩家管理权限，不完成活动，也不执行归集。

## 配置变化下的商路

新建商路必须符合当前运时与节点上限。已保存商路超出新限制时仍可查看，运输暂停并显示限制原因，可按原权限停用、撤单或双方确认改道。暂停不消耗当期维护，不改变原托管物资、冻结总运时或已完成进度，不阻止其他有效商路处理。极端超长的历史路线用 `Integer.MAX_VALUE` 表示不可执行运时，不会溢出为零。

新市场购买不能选择受限路线。原已付款订单继续保留托管并按原稳定事务查询国库回执，不能因重读失败重复付款或免费交货。比较结果排除不符合当前限制的路线；恢复配置后原货物按保存进度继续。

## 交易积压与停服

国家资源出口和市场付款分别维护持久化的首次请求/到期重试轮转游标。每轮各查询不超过批次上限的两个候选队列，实际派发不超过该上限，空队列不浪费名额；游标与租约一起提交或回滚。持续新请求不会永久压住旧重试，旧重试也不能独占全部名额。原事务 ID、退避、租约、国库回执及退款边界保持一致。

专用存储线程关闭时拒绝后续提交，未开始而被强制取消的任务得到终态异常；已经开始的任务由实际执行结果完成。线程未终止时保留数据库连接并报告错误，避免把仍在写入的连接提前关闭。详细线程边界见[架构](architecture.md)。
