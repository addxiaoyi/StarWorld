# 国家金币与城市实物市场

市场出售城市仓库内的真实物品，使用 StarCore 现有国库金币结算，并通过已登记商路交货。1.5支持分批购买，1.8增加双方确认的未交货退款。付款复用核心 `NationTransferService`，退款依赖[上游候选契约](../upstream/starcore/README.md)的原子逆向付款和持久回执。核心自己的抽象国家资源订单簿仍由 StarCore 管理；小麦、面包和 CE 菜肴不被当作国家资源 ID。

## 游玩流程

1. 卖方城市管理者用 `/sw deposit minecraft:bread 64` 存入真实物品，再执行 `/sw market sell minecraft:bread 20 1.25`。20 个面包立即进入挂牌托管，原始总价为25.00国家金币，可由多个买家按数量分别购买。
2. 两城建立一条从卖城正向通往买城的有效商路，参考 [logistics.md](logistics.md)。跨国战争或未知外交关系、停用路线/节点、失地、未加载或损坏的节点会阻止新购买或付款。1.7已绑定物理通道的路线还要求全程道路/水路和沿途领土现场通过；路径中断时仅核对历史付款，不发起新转账。每次购买数量不得超过商路单周期容量；原始挂牌可以大于单次运力。
3. 买方国家创始人或管理员同时具有本城管理权限时，执行 `/sw market buy <挂牌UUID> <卖城至本城商路UUID> 7`，预留7个面包并支付8.75金币；省略数量则购买当时全部剩余量。普通市长不能支出国家金币；同国城市间使用实物贸易。
4. 系统仅预留本次份额，持久保存其数量、精确金额、购买请求和国家付款ID；剩余量仍可购买。后台核对双方当前归属、外交和商路后，调用核心原子转账。付款确认后，该份额进入独立单向运输货单。
5. `/sw market orders` 查看付款状态、原国家凭据与物流单 UUID；`/sw trade list` 查看实际运输。买城只有在物流单 `COMPLETED` 时才收到物品，战争、维护不足或仓储满等会暂停，货物继续托管。

`/sw market-menu` 或发展面板的市场入口可分页查看挂牌；点击商品提供带挂牌 UUID 的购买命令，需要玩家明确填写正向商路。展示物品不能被取出。

| 命令 | 用途 |
| --- | --- |
| `/sw market list [页码]` | 查看可用挂牌，每页十项 |
| `/sw market mine [页码]` | 查看本城所有状态的挂牌 |
| `/sw market sell <物品ID> <数量> <单价>` | 城市管理者托管整批实物；单价为普通十进制、最多两位小数 |
| `/sw market buy <挂牌UUID> <正向商路UUID> [数量]` | 国家创始人/管理员确认国库支付 |
| `/sw market orders [页码]` | 查看本城作为买方或卖方的购买单 |
| `/sw market cancel <挂牌UUID>` | 关闭仍有可买余量的本城挂牌，只退未预留部分；原仓有空间才退还 |
| `/sw market cancel-buy <购买UUID>` | 仅撤销从未派发的 `PENDING` 份额；开放挂牌恢复可买量，已关闭挂牌则退回卖仓 |
| `/sw market retry <购买UUID>` | 原付款国创始人/管理员用同一国家凭据恢复对账 |
| `/sw market refund <购买UUID>` | 原买方国家创始人提出已付款、尚未交货份额的全额退款 |
| `/sw market refund-accept <申请UUID>` | 原卖方国家创始人同意，原子冻结购买与运输 |
| `/sw market refund-cancel <申请UUID>` | 双方任一国家创始人在确认前撤销申请 |
| `/sw market refund-retry <申请UUID>` | 双方任一国家创始人按原退款ID重试待核对或失败的返款 |
| `/sw market refunds [页码]` | 查看本城退款状态及等待原因 |
| `/sw market history [物品ID]` | 最近十份已付款且已转入物流的价格记录 |
| `/sw market stats [物品ID]` | 按物品统计已完成实际交货的订单、数量、总额、加权均价和完成周期；付款或运输中不计入 |

`SHIPPED` 和价格历史表示货物已经转入运输托管，不能据此认定买城已经收货。实际到货以物流完成收据为准。

`/sw market stats` 和 `StarWorldApi.marketDeliveryStats` 只统计物流订单已经进入 `COMPLETED` 的购买份额。后台每轮按 `dispatch-batch` 上限追踪持久物流收据的 sequence 游标，把新完成的市场交货在同一事务内记入全服/卖城/买城聚合和唯一购买凭据；重启或重试不会重复累计，旧版完成记录也会从游标0有界回填。尚未轮转到的收据暂不反映在统计中，查询不主动推进游标。

聚合按物品保存每份购买的真实数量和挂牌单价，使用精确十进制计算总额与加权均价，可按城市作为买方或卖方过滤；累计总额不套用单笔国库转账的金额上限。`PAID`、`SHIPPED`、暂停和失败订单不会提前计入交货统计；统计查询仅分页读取聚合，不扫描全部订单，不发物品、不改变付款或物流状态。业务去重凭据和统计游标不按审计保留天数删除。

## 付款与恢复

| 购买状态 | 持久语义 |
| --- | --- |
| `PENDING` | 已锁定实物，等待首次派发 |
| `IN_FLIGHT` | 已取得派发租约，核心可能已经提交；崩溃后等待租约到期再核对同一 ID |
| `RETRY` | 接口暂不可用、路线/归属阻塞或尚无可核实回执，按原 ID 重试 |
| `REJECTED` | 核心明确拒绝，例如金币不足；原物仍锁定，治理者可修正条件后重试 |
| `REVIEW` | ID 冲突或回执内容不符，保留托管并要求核对；不会发货 |
| `PAID` | 核实核心持久回执，尚待成功创建物流单 |
| `SHIPPED` | 托管原物已在同一 SQLite 事务内交给单向物流 |
| `REFUNDING` | 双方已同意退款，货物冻结，等待返款回执或原仓接收 |
| `REFUNDED` | 原付款已逆转，原物已一次性退回原卖仓 |
| `CANCELLED` | 首次派发前已取消，份额恢复可买或退回已关闭挂牌的卖仓 |

每个数据库实例保存自己的随机命名空间，购买 UUID 对应稳定 `starworld:market:<namespace>:<purchase>` 国家事务 ID 和物流 ID。核心回执必须逐项匹配 ID、付款国家、收款国家、精确金额和 `OTHER` 类别；不以“调用未抛异常”当作到账。相同请求ID搭配不同挂牌、商路、买方、数量或“全部/显式数量”模式会被拒绝；省略数量的重放仍返回首次冻结份额，不会买走后来释放的库存。

核心已支付、本地确认前退出时，重启先查询原回执；原子国库服务不会再次扣款。路线或归属在付款后变化时仍查询历史回执，但不会在无效路线下发起新付款。`PAID` 发货失败保留原托管，有限批处理与持久退避让后续可处理的购买继续前进。

付款与物流不在一个跨插件数据库事务中；持久 outbox、核心原子回执和本地幂等交接连接这两个边界。只有完全未派发的购买可直接取消。已经尝试付款的订单不能因为本地异常自动退款；已支付物流不能使用普通易货撤销或未付款报价过期退款。

1.8退款由买方国家创始人申请、卖方国家创始人确认；申请本身不暂停交货，接受时再次检查尚未完成物流。确认在同一SQLite事务冻结购买、货单和待确认改道。此后停止运输进度及维护，不能解除冻结继续交货。每个购买份额只使用一个确定的退款ID；确认前撤销、再次申请也保留该ID。

退款队列以有限批次、公平轮转、30秒租约和持久退避调用核心原子退款。原付款与逆向回执必须匹配国家、金额和原事务ID，只有成功状态但没有回执时继续等待。余额不足、接口缺失或归属变化保持冻结；归属变化仅查旧回执，不发起新返款。返款完成后，检查原仓容量和原归属，再在一个本地事务内归还本份额、更新挂牌余额及完成退款；失败时钱已返还而货物继续托管。已交货订单拒绝退款，历史已付款发货记录保留，退款货物不计入已完成交货统计。

卖方撤销或挂牌到期只退还尚未预留的余量，已付款和已预留份额继续使用原凭据交付。关闭后取消从未派发的购买，也只退还该份额。满仓、国家改属或无法证明原国归属时，原物继续托管，既不丢弃也不给新所有者；轮转检查不会让这一条永久阻塞其他到期挂牌。

## 配置与能力降级

首次启动生成独立 `market.yml`，已有文件不覆盖。默认值如下：

```yaml
market-version: 1
max-listings-per-city: 20
max-open-purchases-per-city: 100
listing-lifetime-periods: 48
dispatch-batch: 10
max-units: 2304
maximum-unit-price: '1000000.00'
items:
  - minecraft:wheat
  - minecraft:bread
  - minecraft:oak_log
  - minecraft:oak_planks
  - minecraft:iron_ingot
  - minecraft:arrow
  - minecraft:shield
  - minecraft:paper
  - kaleidoscopecookery:baozi
  - kaleidoscope_tavern:wine
```

只允许白名单实物，CE ID 必须真实可解析，不能用配方 ID、显示名或临时石头替代。每城未结束挂牌、未完成付款/发货准备、数量、单价、金额与派发批量有硬上限。未完成购买默认每城100份（最大1000），买卖两端均计入；完成发货或撤单释放名额。旧配置缺少该项时使用100。金额使用 `BigDecimal`，最多两位小数，必须在 0.01 至 1,000,000,000,000.00 之间；不会舍入玩家价格。

缺少 `NationTransferService` 或核心未启用时，状态页明确显示国家金币市场待恢复，不使用无稳定业务 ID 的个人 Economy 转账，也不将独立 debit/credit 拼成国家原子支付。现有实物产业和易货链可继续使用。高于当前的市场配置/数据库版本拒绝加载并保留原文件。

## Java 与测试边界

公开只读查询为 `StarWorldApi.marketListings(limit,offset)` 与 `marketPurchases(city,limit,offset)`，见 [API.md](API.md)。内部 `MarketService` 与 `LogisticsService` 共用 `WorldStore` 串行 IO 和事务；写入调用方必须先由 Paper 主线程捕获当前城市、治理、领土、节点与外交证据，内部方法不构成免权限玩家 API。

市场schema 1→2在一个事务内迁移：保留命名空间、国库ID、物流ID及旧订单状态，把整批数量分配到四项余额，并将价格历史改为按购买去重。1.8推进到schema 3，增加退款账本及队列、更新未结束购买索引；不自动为旧交易申请退款。迁移失败整体回滚，不删改旧存档。原始数量恒等于可买、预留、已发货、已退回之和，数据库触发器强制校验。

真实SQLite回归覆盖挂牌扣货一次、多买家份额与并发防超卖、迁移中断回滚、付款丢 ACK/重启、回执冲突不发货、发货事务失败回滚、未派发撤单、满仓到期与公平轮转；控制器另验证创始人权限和异步回调再次授权、停用节点后不调用新转账。核心适配器测试按审计的公开接口精确签名执行。实际服务器、客户端与最终通过数量另见 [test-results.md](test-results.md)。
