# 完整动态文明系统后续设计

以下是后续设计，不计入 0.1.0 已完成功能。

## 地理与交通

已登记区块聚合地理分区，只在登记/领土变更时增量更新。道路、桥梁、港口、关隘为交通节点，边保存运营成本/容量/风险；用显式货单流转，不每tick全世界寻路。失去节点/领土则中断或改道，核心仍拥有战争/领土。

transport 系数影响货单时间与损耗；military 通过核心未来公开的补给扩展事件影响战局，不直接改战争表。耗尽矿区通过勘探、进口和国家决策解决，不重复登记刷新。

## 产业与城市

复用经审计的核心 ProductionService/ResourceProcessingService，核心拥有抽象国家资源与通用设施，StarWorld 专管地区/实体物品/生活产业。国家资源输出采用本地outbox稳定ID → NationResourceTransactionService请求 → receipt → ACK，测试核心提交/本地ACK前崩溃后再开放。

市场采用跨城市托管货单/供需/限量报价，资金使用核心已有经济/交易服务。新增仓库、市场、兵营、学院的维护/容量/补给/教育作用，城市规划和特色只持有扩展属性，繁荣贡献通过核心公开入口提交。

## 文明与事件

生产/贸易/战争/文化行为生成有稳定ID的倾向贡献，文化沿有效商路传播并按区域保存。专长受资源/科技/政策约束，有冷却与相互制约，不按在线人数刷倍率。

新增洪水、饥荒、商业繁荣、文化节庆、边境争端、衰落/复兴。触发因素取核心天气/时代/外交/战争和本地粮食/交通，支持权重、前提、互斥、冷却及历史。方块变化只能目标区域限量调度并可回滚。

## 生活联动与 Folia

Cookery/Tavern 需要上游 post-commit、交易ID、玩家/位置/数量的完成回执；Deco需要稳定家具ID及放置/拆除后事件；MusicPlus需要会话结束/取消、参与者、场地回执。没有可靠证据不自动奖励城市。生活职业贡献还需实际消费、限额、防自刷和收益审计。

Folia 按 architecture.md 的不可变核心快照、区域验证回执、实体调度进行改造。每阶段需自动化/崩溃测试、Paper双玩家权限/GUI/重启测试、配置迁移回归与可选依赖存在/缺失测试；正式 Folia 真服通过后才声明支持。
