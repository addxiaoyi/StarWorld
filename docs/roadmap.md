# 已实现范围与后续边界

1.4.0 继续使用九类设施、五文明、十一种条件事件、城市与国家发展、有限路网、实物贸易、生活职业和幂等国家资源出口。后续已增加地区地图册、文化衰减、双边改道、运力查询、金币实物市场、审计归档、经营反馈、在线备份、六种救灾方案、公共工程与真实生活需求。版本进度见[开发计划](development-plan.md)，逐项实现见[需求映射](requirements.md)，验证结果见[测试结果](test-results.md)。以下扩展已纳入本轮继续开发，依赖与状态见开发计划；只有完成相应验证才会改为支持声明。

## 地理与交通

现有地理以设施登记和有限勘探的区块增量建立地区，地图册分页显示储量/恢复/文化/设施，交通按有限显式节点路线运行。每城勘探地区上限为128；勘探只读取玩家所在已加载区块并复核本城、本国领土。失去节点/领土或战争会暂停真实物资运输；运力查询展示共享瓶颈、维护和暂停原因，双方确认可改走已登记同方向路线。后续可增加地区合并和地图式布局。道路连续性、河流可航性和天然关隘识别目前不做整图自动推断，不能扫描所有区块或每 tick 全世界寻路。

0.4 已增加有限路线成本规划：管理者可以比较同端点已声明路线的周期、距离、容量和节点数。它是只读规划投影，保留停用路线供成本比较，不改变授权或运输状态。第三国过境暂不实现，因为 StarCore 没有公开通道许可/过境回执；端点城市之外的节点仍被拒绝。

当前只证明登记节点本身的领土与锚点，不证明节点间每个区块的道路、可航水面或过境许可；不向第三国节点收维护费，也没有第三国过境/关税系统。完整地缘封锁需要有限、可复核的通道或地段模型，再接入核心公开外交/领土快照，不能把一条声明路径说成全程实际可通行。

现有军需与地形已经通过StarCore公开army_combat贡献点影响有效设施区块的实际军队伤害，并受核心最高值聚合规则限制；不影响玩家PVP或自动改ArmyService补给。后续扩大到国境战场、围城、连续补给线需要更精确的核心快照/回执契约，不能写战争表或复制国家战争系统。

## 城市、文明与经济

现有规划、专长、知识、文化、本地繁荣和资源短缺使城市形成分工。实物易货与金币挂牌共用仓储托管和运输；1.5正在实现和验收按数量分批购买；金币市场复用核心原子国家转账、稳定业务凭据和精确金额，记录已付款发货时点的价格。0.4增加实际完成交货的有界统计归集。分批购买以独立份额、付款与物流凭据保持守恒；后续继续增加税费和可核对退款；当前不做限价撮合或个人钱包支付。不能凭空发金币、拼接非原子的两次收付，或把国家抽象资源当 ItemStack 别名。

地区文化通过有效设施和真实完成贸易传播，公开核心政策调整新影响增长，持久时钟按配置衰减且不离线多步追赶。后续可增加与明确人口/迁移证据相连的文化交流、更细产业优势约束；当前没有独立人口模拟、选举、国政或另一套国家科技树。国家科技、政策、时代、外交和繁荣继续来自 StarCore。

国家发展倾向由当前归属城市的真实产出、贸易、军需和文化累计聚合，专长要同时达到对应行为分数和知识门槛。国家创始人可以选择农业、工业、贸易、军事或文化专长；存在产业取舍与六周期冷却。失去贡献城市时条件与加成随之减少，不把已失去城市的历史永久留在原国家加成里。

城市繁荣没有跨库自动回写国家。上游 `modifyProsperity/recordEvent/addChunkContribution` 缺稳定业务ID与完成回执，需先提供幂等接口，再扩展独立outbox。国家资源已有安全receipt不意味着所有跨库mutation都同样安全。

十一种事件已经影响真实产业、库存压力和城市发展，余波与历史可跨重启保留。边境资源争端将有效登记地区的正资源储量、四邻外国领土及对应国家的战争/明确敌对关系关联，历史记录具体产地、对端和资源；不自动宣战或裁决矿权。后续可增加双方申诉和核心外交处理接口。灾害当前改变经济状态，不自动改河道、淹毁建筑或接管核心天气。

## 森罗与内容生态

Cookery/Tavern当前通过已交付的真实CE商品消费联动；期待上游增加提交成功后携稳定交易ID、玩家/设备、位置、实际数量的完成事件，才适合自动城市产出归因。Deco当前使用公共CE家具API显式登记/复核，未来稳定目录与家具放置/更新/拆除提交事件可减少轮转查询；不读取私有状态或NBT。

MusicPlus当前无公开演奏完成API。StarWorld自己的受控现场演奏有真实声音、乐器、听众和持久回执；不能把它说成自动监听上游MIDI或 `/kmusic`。预留公共完成端口等待上游版本化API。整套CE/森罗多人联服、热重载、强制删除和声效体验应分别留真服证据，不以模拟fixture代替。

## Folia与规模验证

当前明确不支持Folia启用，原因是StarCore公共可变服务缺区域线程契约。所需步骤：核心发布不可变带版本状态与权限快照；锚点/家具在位置区域调度器验证；背包/GUI/声音在玩家实体调度器；跨区域听众只汇聚不可变证据；回执核实归属版本、退休与停服；通过跨区、传送、退服、区块卸载、转国、重启真服测试后再声明支持。

已有有限城市/节点/货单/outbox/归档批量、市场持久退避与公平轮转、非重叠调度。千城基线实际运行 2,000 设施和 3,000 次 SQLite 结算，并核对重启后 1,000 城同周期不重复；范围与机器结果见 [scale.md](scale.md)。审计在同库事务无损压缩，保留所有业务凭据，见 [storage-maintenance.md](storage-maintenance.md)。下一步应测量真实 Paper 权限/锚点摘取、长时间 IO 积压、多种产业和大量运输/付款、慢库与故障注入、在线备份及磁盘容量；不能由纯存储测试推定服务器在线容量，也不能靠无限提高每 tick 工作量掩盖问题。

在线 SQLite 备份使用 `VACUUM INTO`、完整性检查、版本读取、SHA-256 和原子替换，并在真实存储测试中重复备份已提交写入，验证快照可独立重开读取。Paper 长时间 IO 积压、跨文件系统灾备、在线世界压力和 Folia 仍需专门环境。
