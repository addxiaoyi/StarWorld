# 存档维护与审计归档

StarWorld 的 `starworld.db` 只保存扩展状态，通过串行 IO 与 SQLite 事务写入。数据库使用 WAL、`synchronous=FULL`、外键和 5 秒 busy timeout。城市、国家、领土、科技、政策、国库和抽象资源权威仍在 StarCore，维护任务不操作其数据库。

## 有界自动维护

`config.yml` 提供：

```yaml
maintenance:
  audit-days: 30
  retain-periods: 1000
  batch-rows: 100
```

每 30 次成功进入的扩展调度尝试一次维护，沿用非重叠调度和同一串行存储入口。每轮分别最多处理 `batch-rows` 条旧审计、结算报告和设施周期记录，不一次清空全库。

| 数据 | 处理方式 |
| --- | --- |
| 超过 `audit-days` 的 `audit` 行 | 版本化 UTF-8 二进制编码、GZIP 压缩和 SHA-256 校验后写入 `audit_archive`，在同一事务内删除对应原行 |
| 早于 `currentPeriod - retain-periods` 的 `settlement` 报告 | 按周期/城市有限删除旧报告；城市 `last_period` 仍保留防重复生产的水位 |
| 同样过期的 `evolution_facility` 记录 | 还必须早于该城当前 `last_period`；当前设施维护/容量证据保留 |
| 库存、托管、付款、outbox 与业务幂等凭据 | 保留，不按审计保留期清除 |

允许审计保留 1–3,650 天、报告保留 1,000–1,000,000 周期、每类批量 1–1,000 行。非法配置拒绝加载。周期是游戏结算周期，不等于天数；默认 300 秒下 1,000 周期约为 83 小时 20 分钟，修改周期后应重新评估保留窗口。

归档和删除共用一个事务：编码、写入或后续删除失败会整体回滚。归档保留每条审计的原 ID、时间、actor 和 action；首末 ID 表示该批的范围，不表示中间 ID 必定连续。归档仍在同一个 SQLite 文件内，属于无损压缩归档，不是外部备份，也不会自动执行 `VACUUM` 或承诺文件立刻缩小。

## 查询与恢复

管理员用 `/sw maintenance` 查看最近一次维护结果，以及首批最多 20 份归档的行数、压缩字节和 SHA-256。该命令只查询，不触发全库清理或导出；归档按 ID 顺序显示。

内部 `LedgerMaintenance` 提供以下存储操作，须放在串行 IO 中调用：

| 方法 | 合同 |
| --- | --- |
| `sweep(period,nowMillis)` | 同库事务内完成三个有界维护步骤，返回实际处理行数 |
| `archives(afterId,limit)` | 递增 ID 游标分页，`limit` 为 1–100，返回元数据 |
| `readArchive(id)` | 先验证压缩载荷 SHA-256，再解码格式版本、行数和 UTF-8 文本长度；不符或存在尾随数据时失败 |

没有“按日志重新发货/退款”入口。归档审计用于追查，不构成物品、国家支付或背包交接完成的权威凭据。国家市场对账仍读取核心原事务 ID 的真实回执；玩家文件与数据库之间未决物品转移仍按 `/sw pending` 和管理员核对流程处理。

## 备份与升级

正常停服并等待 IO 关闭后，备份整个插件目录和当前插件版本，包含配置、数据库及仍存在的 `-wal/-shm` 相关文件。恢复时使用对应版本。在线备份应使用 SQLite 提供的一致快照机制，单独复制正在写入的主 `.db` 文件不足以保证完整。

基础库保持 schema 2；文化衰减、市场、物流等使用独立版本表和加法式建表/索引，不在其他模块初始化时覆盖共享版本。各模块拒绝其识别的未来 schema 版本；旧 0.2 插件会忽略自己不认识的新表，不能依靠它自动阻止所有降级。降级必须恢复该版本对应的备份，不能把已升级的新库直接交给旧插件。升级前保留配置定义 ID：已登记的地形、文明、物品和设施 ID 是持久键，重命名需要明确迁移。

`LedgerMaintenanceTest` 覆盖有界归档、重开后读回、哈希破坏拒绝、事务失败回滚、历史报告裁剪和幂等状态保留。最终测试和产物身份以 [test-results.md](test-results.md) 为准；纯存储规模结果见 [scale.md](scale.md)。
